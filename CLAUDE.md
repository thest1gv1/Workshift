# Workshift — контекст проекта

## Описание

Мобильное PWA приложение для сотрудников банка. Используется в течение рабочей смены для учёта клиентов и формирования отчёта в конце дня.

## Текущий стек

- Next.js 16 + TypeScript
- Tailwind CSS v4 + CSS Modules
- shadcn/ui
- Nano Stores
- свой vps (деплой)
- PostgreSQL
- Drizzle ORM + pg (драйвер PostgreSQL)
- Next.js API routes

## Работа с БД

- Схема таблиц: `src/lib/db/schema.ts`
- Запросы: Drizzle ORM; `pg` используется как драйвер
- Генерация миграций: `npm run db:generate`
- Применение миграций: `npm run db:migrate`

## Экраны

- `/login` — авторизация
- `/` — текущая смена (главная)
- `/add` — добавить/редактировать клиента
- `/history` — список прошлых смен
- `/history/[id]` — смена с возможностью редактировать суммы по услугам
- `/stats` — статистика по месяцам
- `/settings` — настройки

## Флоу

1. Мастер авторизуется (один раз, потом автоматически)
2. В течение дня добавляет клиентов в текущую смену
3. В конце дня завершает смену — видит итоги, копирует отчёт
4. Смена уходит в историю, можно редактировать только суммы по услугам

## Режим обучения разработчика

1. не писать код за пользователя пытаться донести информацию так чтобы он понял и постарался сам, если уж он требует ответ и не может сам, помогай с кодом.

2. Старайся дать по возможности абрастрактный пример чтобы он больше понял

3. дополняй теорией

## Деплой

**Стек на VPS:**

- Ubuntu, Nginx как обратный прокси
- PM2 для управления процессом Node.js
- PostgreSQL локально на сервере

**Процесс обновления:**

1. `git push origin main` — пушишь код на GitHub
2. На VPS: `git pull` — тянешь изменения
3. `npm ci` — устанавливаешь зависимости, включая Drizzle Kit
4. `npm run db:migrate` — применяешь новые миграции
5. `npm run build` — собираешь Next.js приложение
6. `pm2 restart workshift` — перезапускаешь процесс

**Миграции БД:**

- Drizzle-миграции и снимки схемы: `migrations/drizzle/`
- Старые `migrations/001_`–`004_` сохранены как история и тестовые фикстуры
- После изменения схемы: `npm run db:generate`, проверка SQL, затем `npm run db:migrate`
- Начальная миграция использует `IF NOT EXISTS` для совместимости со старой базой; повторный запуск управляется журналом Drizzle
- Последующие миграции выполняются один раз по журналу; уже применённые файлы не редактировать
- Перед применением на VPS проверять SQL и делать резервную копию
- Интеграционные проверки на временных локальных базах: `npm run test:db`
