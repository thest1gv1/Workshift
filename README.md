# Workshift

Мобильное PWA приложение для сотрудников банка. Используется в течение рабочей смены для учёта клиентов и формирования отчёта в конце дня.

## Стек

- Next.js 16 + TypeScript
- Tailwind CSS v4 + CSS Modules
- shadcn/ui
- PostgreSQL + Drizzle ORM (драйвер `pg`)
- PM2 + Nginx (VPS)

## Что сделано

- Создал Next.js проект с TypeScript, Tailwind, shadcn
- Настроил дизайн систему — токены цветов, шрифты Onest и Unbounded
- Сверстал главный экран — карточка смены, список клиентов, кнопки
- Сверстал форму добавления клиента — поля, чипы услуг, тип
- Сверстал экран статистики и настроек
- Вынес компоненты — ShiftCard, StatBox, ClientRow, BottomNav
- Подключил Nano Stores — settingsStore и shiftStore
- Сделал рабочую логику — добавление клиентов, динамические цифры, прогресс план
- Задеплоил на Vercel

- Подключил PostgreSQL — создал БД, таблицу клиентов, настроил подключение через `pg`
- Написал API routes — GET, POST, PUT, DELETE для клиентов
- Реализовал редактирование клиента — загрузка данных по id, обновление через PUT
- Задеплоил на VPS с PM2 и Nginx — обратный прокси, несколько проектов на одном сервере
- Настроил PWA — манифест, иконки, поддержка установки на домашний экран

## Локальная база данных

1. Запусти PostgreSQL и Redis: `docker compose -f docker-compose.dev.yml up -d`.
2. Если `.env.local` ещё нет, скопируй `.env.example` в `.env.local` и задай `AUTH_KEY`. Существующий файл не перезаписывай: обнови только нужные значения.
3. Установи зависимости: `npm install`.
4. Создай таблицы: `npm run db:migrate`.
5. Запусти приложение: `npm run dev`. Адрес: `http://localhost:3000`.

Локальный `DATABASE_URL`: `postgresql://workshift:workshift_local@localhost:5433/workshift`.
Redis доступен на `localhost:6380`; приложение пока его не использует.
Порты контейнеров опубликованы только на loopback. Данные хранятся в отдельных Docker volumes.

## Drizzle и миграции

Таблицы `clients` и `shifts` описаны в `src/lib/db/schema.ts`. Подключение — в `src/lib/db.ts`.
Drizzle строит запросы из TypeScript, а `pg` остаётся драйвером подключения к PostgreSQL.
Конфигурация `drizzle.config.ts` читает `.env.local` / `.env` через загрузчик Next.js; переменная окружения `DATABASE_URL` имеет приоритет.

После изменения схемы:

```bash
npm run db:generate
# Проверь созданный SQL в migrations/drizzle, затем примени его:
npm run db:migrate
```

`db:generate` создаёт SQL-файл и снимок схемы, но не изменяет базу. `db:migrate` применяет ещё не выполненные миграции и записывает их в `drizzle.__drizzle_migrations`. Команду можно запускать повторно. SQL, снимки и журнал из `migrations/drizzle` нужно коммитить вместе со схемой.

`npm run db:studio` открывает инструмент просмотра и редактирования базы.

Начальная миграция также поддерживает базы, созданные старыми миграциями `001`–`004`: она использует `IF NOT EXISTS` и сохраняет данные. Старые файлы в корне `migrations/` оставлены как история и тестовые фикстуры; вручную применять их больше не нужно. Эта совместимость относится к схеме проекта, а не к произвольно изменённым таблицам.

## Проверки базы

```bash
npm run test:db
```

Тест использует локальную PostgreSQL на порту `5433`, создаёт временные базы `workshift_test_*` и удаляет их после проверки. Базу приложения не меняет. Проверяет миграции на пустой и старой базе, повторное применение, API, статистику и откат транзакции. При необходимости задай отдельный `TEST_DATABASE_URL` локального сервера; пользователь должен иметь право создавать базы.

## Обновление на VPS

На сервере укажи `DATABASE_URL` своей серверной базы. Локальные Docker-реквизиты предназначены для разработки.

```bash
git pull
npm ci
npm run db:migrate
npm run build
pm2 restart workshift
```

Drizzle Kit находится в devDependencies, поэтому для этого процесса обновления нужен `npm ci` без `--omit=dev`. При первом переходе с ручных миграций сделай резервную копию существующей базы. Контейнер PostgreSQL не переносит данные с VPS автоматически.
